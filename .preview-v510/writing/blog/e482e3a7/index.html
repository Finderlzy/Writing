日常维护、风控应对与常见故障

订阅成功不等于一劳永逸。前面做的所有事，都是为了让 Claude 觉得你是一个普通的海外用户；订阅之后，你也要继续像一个普通用户那样使用。

这一章分三部分：日常使用的注意事项、账号受限后的处理，以及卡住时的排查。

订阅之后，继续像普通人一样用

风控最敏感的是“不像人”的行为。下面几件事，最好一直注意。

不要刚订阅就猛用

新付费的账号，前几天属于观察期。不要第一天就连续十几个小时高并发使用、一下子把额度刷满。像一个正常上班、学习的人那样，由浅入深地增加使用量。

保持出口 IP 稳定

不要今天用美国住宅、明天切到日本节点、后天又在没开代理的情况下裸连。短时间内跨大洲的 IP 漂移，在安全系统眼里很像“账号被盗”或“多人在异地共享”。

只要你用 Claude，就固定用自己搭的那一条住宅出口。主节点和备用节点之间切换没关系，它们的出口是同一个。

控制登录设备

不要把账号分给多个朋友，也不要在四五台设备上同时保持长连接。同一时间保持一两台主力设备在线就够了，比如自己的电脑和手机。

在陌生设备上登录之前，先确认那台设备的代理已经打开，DNS、WebRTC 没有泄漏。

不要拿网页版账号做反代或 API

市面上有些工具声称可以把网页版 Claude 账号转成 API，供第三方软件调用。这是官方打击力度最高的行为之一。 网页版 Pro 账号只供人在官方网页和 App 里使用；机器爬虫的特征很容易被识别。

即使只有你一个人用，也不要这么做。

续费

iOS 订阅：苹果会在到期前 24 小时自动尝试扣款。提前一两天用支付宝买礼品卡，充值到美区 Apple ID，保证余额足够支付订阅价和可能的销售税，系统就会自动续期。

安卓订阅：我还没有走通安卓的支付，续费方式也无法给出验证过的步骤。

账号受限之后

Google 账号被停用

Google 账号被封，不一定是你做错了什么。新注册的号本来就容易被风控误伤。Google 给了申诉机会，一般很快能通过。

  1. 登录被封的账号时，页面会提示账号已停用。点页面上的申诉按钮（“申请恢复”或类似字样）。
  2. 按提示填写辅助验证手机号，申诉理由简单说明这是你自己在正常使用的账号即可，比如：

text This is my personal account for daily study and communication. I follow all Google Terms of Service. Please help restore it.

  1. 等 Google 回复邮件。审核期间保持代理开启，网络环境不要变。
  2. 申诉通过后，回到iOS 端或安卓端的“先用两天”那一节，继续用两天，没问题再往下走。

Claude 账号被停用

先访问 Anthropic 官方支持中心，通过官方渠道提交复核申请。

申诉时注意：

  • 态度诚恳，说明自己是真实的个人用户，平时用来学习、写代码或做研究；
  • 说明账号只由你一个人使用，没有共享，也没有接自动化脚本；
  • 可以提一句“可能是网络环境波动导致的自动误判”，但不必展开网络配置的细节；
  • 不要提交伪造的材料。

下面是一段可以参考的英文模板：

Subject: Request for Account Review - [你的注册邮箱]

Dear Anthropic Support Team,

I am writing to request a review of my Claude account ([你的注册邮箱]),
which was recently suspended.

I am an individual user and I rely on Claude for my daily study and
programming work. I have always followed the Anthropic Terms of Service
and Acceptable Use Policy. This account is used only by me, for personal
purposes, with no automated scraping or shared access.

I suspect this may be an automated false positive. I would appreciate it
if you could take a manual look at my case and let me know if there is
anything I need to correct.

Thank you for your time.

Sincerely,
[你的姓名或拼音]

常见故障

测出来好几个不同的 IP

ipinfo.io 上是一个 IP，商家后台写的是另一个，别的测 IP 网站又是一个，DNS 检测里还有别的。看懵了很正常，这几个 IP 各是各的东西，不一定是哪里出错。

先回忆方案一的结构：请求先到服务器，只有 Claude 和 ipinfo.io 再从服务器转给 ISP，其他网站从服务器自己的出口出去。按这个去对：

  • ipinfo.io 上看到的是 ISP 的 IP。 它是住宅 IP，也是 Claude 看到的那个。
  • 商家后台、别的测 IP 网站看到的是服务器 IP。 服务器大多是机房 IP；ISP 流量少，所以只让 Claude 和 ipinfo.io 走它。
  • DNS 检测里列出来的是 DNS 服务器的 IP。 防泄漏那一步让代理软件通过 Cloudflare、Google 这些服务去查，所以显示的是它们的地址，不是你的，也不在国内，这正是我们想要的。
  • WebRTC 检测里 Local IP、Public IP 显示 -，说明 WebRTC 已经被管住，什么 IP 都没交出去，也是对的。

方案二没有 ISP 这一层，ipinfo.io 和其他网站看到的都应该是服务器的住宅 IP。如果不一样，先检查代理是不是全局生效。

怎么确认“1 人独享”真的只有我在用

说实话，没法百分百确认，只能间接看：

  • 连续几天测 IP，地址一直不变；
  • Scamalytics 的风险分一直很低，没有慢慢变高；
  • 买之前问清楚商家，是“独享 IP”，还是只是“独享带宽”。

所以建议先买一个月试试。

装过了，想重装

在服务器上运行同一行脚本命令。脚本发现装过会先问你，输入 y 删掉旧的重新装，输入别的什么都不动。

重装后节点链接会变，代理软件里要删掉旧节点，重新导入。

重装前先关掉电脑上的代理软件

SSH 可能正走在这台服务器的节点上。脚本一删旧节点，SSH 就断了，出现 Connection to ... closed by remote host。先关掉代理软件，或者关掉 TUN / 全局模式，再 SSH 连服务器。

如果已经遇到了，关掉代理（或者重启电脑）再连一次，重新运行命令就好。

SSH 端口不是 22

有的商家后台会多写一个端口，是一串四五位的数字。这时候照正文输 ssh root@你的服务器IP，连 password: 都不会出现，屏幕上提示的是：

ssh: connect to host 你的服务器IP port 22: Connection refused

原因很简单：一台服务器上跑着好几个程序，SSH 是一个，节点是另一个。请求送到服务器后，要靠端口决定交给哪个程序。SSH 默认住在 22 号门；商家如果把它改到了别的门，敲 22 号自然没人应。

在命令里加上小写 -p：

ssh -p 你的端口 root@你的服务器IP

你的端口 换成后台“端口”一栏的数字。后面和正文一样：问 Are you sure... 时输入 yes，出现 password: 时输入 root 密码。

SSH 提示 Permission denied

输完密码回车，出现 Permission denied, please try again.，意思是服务器不认这个密码。

先仔细再输一两次。输密码时屏幕上什么都不显示，多一个空格、少一个字符都看不出来。还是不行，按顺序试：

  1. 重置密码。 在商家后台把 root 密码改成一个新的，关掉当前命令行窗口，新开一个重新连接。
  2. 重启电脑，再连一次。
  3. 不用 SSH，从商家后台进服务器。 后台一般有“登录控制器”“控制台”或“VNC”，点进去就是服务器的命令行。在里面用 root 和密码登录，直接把脚本命令粘贴进去运行。
  4. 申请退款。 上面都不行，就找商家退款；还想用这个方案，可以再买一台。

面板的用户名、密码、端口大家都一样，安全吗

用这个脚本装出来的面板，默认用户名 admin、密码 123456、端口 8080，每个人都一样。这是我故意设成一样的，最开始是为了方便远程帮大家排查问题。

别人知道了这套用户名密码，能不能登上你的面板？不能。面板只开在服务器本机，从外网直接访问打不开。要进面板，得先在自己电脑上运行：

ssh -L 8080:127.0.0.1:8080 root@你的服务器IP

这条隧道要输入你的服务器密码。也就是说，面板外面还有一道门，钥匙是服务器密码。除非别人知道你的服务器密码，否则上不了你的面板。

不改也行。想改的话，直接在面板里改最方便。改之前先弄清楚会影响什么：

  • 面板的用户名、密码：不影响节点，节点照常用。
  • 面板的端口：节点照常能用，但下次打开面板时，ssh -L 命令和浏览器地址里的 8080 要换成新端口；脚本的“每周自动更新 Xray 内核”还按旧端口找面板，会一直更新失败。没有特别理由，别改面板端口。
  • 节点的端口：节点会连不上。节点链接里写着端口，代理软件还在按旧端口连。改了要重新导出链接，在代理软件里删掉旧节点再导入。

面板里的位置（以 3x-ui v3.9.0 的简体中文界面为准，升级后菜单可能变）：

  • 用户名、密码：面板设置 → 安全设定 → 管理员凭据。
  • 面板端口：面板设置 → 常规 → 面板监听端口，保存后点“重启面板”。

分流规则具体怎么写

方案一、二的脚本只在服务器上做分流，管的是“到了服务器之后哪些走 ISP”。客户端到节点这一段仍要自己保证 Claude 走代理。这里说的是你已经有别的基础节点、只想让 Claude 走住宅节点的情况。

至少要包含这几个域名：claude.ai、claude.com、anthropic.com，再加上用来检测的 ipinfo.io。

Clash Verge（mihomo 内核）：在规则里加上下面几行，住宅节点 换成你的节点或策略组名字，并放在其他规则前面：

- DOMAIN-SUFFIX,claude.ai,住宅节点
- DOMAIN-SUFFIX,claude.com,住宅节点
- DOMAIN-SUFFIX,anthropic.com,住宅节点
- DOMAIN-SUFFIX,ipinfo.io,住宅节点

Shadowrocket：在“配置”→“规则”里新增 DOMAIN-SUFFIX 类型的规则，域名同上，策略选住宅节点。

v2rayN：照 电脑端那章的规则集，把 claude 规则设成 geosite:anthropic → proxy，再把当前服务器切到住宅节点。v2rayN 的规则只能选“代理 / 直连 / 阻断”，不能直接指定某一个节点，所以“走哪个节点”靠当前选中的服务器决定。

看不懂也没关系：不分流，用 Claude 时全局走住宅节点，最不容易出错。

节点导入小火箭后用不了

节点导入小火箭（Shadowrocket）之后，有的群友能正常用，有的怎么都连不上。原因不太清楚，可能是小火箭版本或设置不同。脚本装出来的主节点是 VLESS 协议，某些版本可能和它配合得不好。

遇到这种情况，直接换一个代理软件：

  • V2Box：免费，有一点广告。本文 iOS 章节以它为例。
  • Tunna：免费，没有广告，但很多群友反馈搜索不到。

下载方式见 客户端配置那章的“准备一个能下载代理软件的 App Store”：把 App Store 换到奥地利，付款方式选 EPS，Bank 选 Bank Austria，PLZ 填 1010。下载完可以把地区改回中国大陆。

提示“购买未完成”

看 注册和订阅那章的“如果提示购买未完成”。核心是：不要连续重试，先让 AI 帮你检查设置，再联系 Apple 客服；拿到 Case ID 后等 72 小时，期间什么都不要改。

遇到 KYC 身份验证

KYC 是身份验证，要求你证明“你是你”。

很抱歉，我没有遇到过 KYC，也没有找到可靠的解决方法，所以没法给出验证过的步骤。遇到的话，可以去官方支持中心看看，或者到社区里找有实际经验的人。
