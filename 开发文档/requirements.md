# 需求：按阶段管理内容，网站只为读者重做（目标版本 5.0.0）

> 写于 2026-10-26。基线是 4.1.0（见 [DEVELOPMENT.md](DEVELOPMENT.md)）。术语以根目录 [CONTEXT.md](../CONTEXT.md) 为准，本文不重复定义。
>
> 标注：【要求】作者明确提出；【选定】作者授权后由 Agent 选定，可以推翻；【假设】待验证；【待决策】还没定。

## 1. 目标与范围

### 为什么改

这个项目最早是为了在多台设备上读自己在 Obsidian 里写的东西。订阅教程带来大量读者以后，网站为了照顾观感一点点加功能，结果自用和读者两个目的混在一个文档风格的站点里，分类和界面都越来越乱。

这一版把两个目的分开：

- **自用**：作者通过 GitHub 同步整个 Obsidian 仓库，在其他设备上阅读全部内容，包括不公开的部分。网站不再承担这个用途。【要求】
- **读者**：网站只展示思考、初稿、博客和作品，按个人博客的样子从头设计。【要求】

### 成功标准

- 作者拿到一篇新内容时，只看 `分类标准.md` 就能确定它属于哪个阶段、放进哪个文件夹。
- 读者打开网站，首页先看到作者的话和博客、作品；进入“全部文章”筛选一次，就能找到想看的阶段或主题。
- 不公开的内容在网站上打不开。
- 除了作者明确要求删除的内容，原有的源文件一篇不少。

### 首期范围

1. 按阶段重新划分文件夹，重写分类标准，把现有内容迁移到新文件夹。
2. 清理不再需要的内容：`02笔记`、`09归档`、`scripts/setup.sh`。
3. 重新划定发布范围。
4. 重做读者前端：首页、全部文章、文章页。

### 非目标

- 用网站做自用阅读，或者给网站加登录、密码之类的访问控制。
- 把 `07自己` 移出公开仓库。作者接受有人翻源码读到它。【要求】
- 保留旧网址。只有 `/tech/subscribe-claude-quick/` 例外，见 R-PUB-4。
- 访问统计和站内搜索。【选定】
- 改写已有内容里的 Obsidian 语法。今后作者会少用复杂语法，但不要求回头修改旧文。【要求】
- 规定生成器、主题和转换层怎么实现。这些交给架构阶段；现有的 Obsidian 转换层允许删除。【要求】

## 3. 三级边界

**Always**

- 构建过程只读取 `docs/`，不写入、不删除；转换和生成都在别处进行。
- 除了第 5 节明确要删的，任何改动都不能删掉 `docs/` 里的内容文件。迁移只移动文件、修正链接，不改正文。
- 改变目录或发布范围时，同步更新 `docs/01系统/分类标准.md` 和项目 `AGENTS.md` 的“项目说明”。
- 手机宽度（375px）下，页面不能出现横向滚动。

**Ask first**

- 删除第 5 节以外的任何内容文件或附件。
- 修改 `README.md`。README 由作者本人维护，过时的说明列给作者，由作者决定怎么改。
- 改动 `docs/.obsidian/` 里的插件配置，包括 Inbox Filer 和 Obsidian Git。
- 增加第三方服务或付费依赖。

**Never**

- 发布收集、系统、自己这三类内容。
- 为了让构建或测试通过而删除内容文件、跳过检查。
- 做首期非目标里列出的功能。

## 4. 用户场景

**S1 作者从收集写到博客。** 作者在 `00收集` 记下一个念头。之后用自己的话写了一篇思考，新建在 `02思考`。几个月后，作者把几篇思考整合成一篇博客，新建在 `04博客`。原来的收集和思考都留在原处，不移动；思考和博客各自成为一篇文章。

**S2 读者从教程进站。** 读者点开视频里的旧链接 `/tech/subscribe-claude-quick/`，被跳转到这篇博客的新地址。读完以后，读者点顶部栏的“全部文章”，按“二次元”标签筛选，打开一篇思考。

**S3 作者在手机上看私人内容。** 作者在手机上通过 GitHub 同步打开 `07自己` 里的一篇。网站上没有这篇，用猜到的网址访问也打不开。

## 5. 功能需求

### M1 内容结构

**R-STR-1 文件夹表示阶段。** 每篇内容的阶段只由它所在的文件夹决定；标签只表示主题，不表示阶段。【要求】对应关系如下：

| 文件夹 | 内容 | 由哪里迁来 | 是否发布 |
| --- | --- | --- | --- |
| `00收集` | 收集 | `00收集` 和 `00收集/灵感` 合并 | 否 |
| `01系统` | 系统 | 不变 | 否 |
| `02思考` | 思考 | `03思考`（不含 `初稿/`） | 是 |
| `03初稿` | 初稿 | `03思考/初稿` | 是 |
| `04博客` | 博客 | `04技术` | 是 |
| `05作品` | 作品 | 不变 | 是 |
| `07自己` | 自己 | 不变 | 否 |
| `09附件` | 图片等附件，只有公开文章用到的才发布 | 不变 | — |

六个阶段文件夹的名字（收集、系统、思考、初稿、博客、作品）是作者定的；编号前缀用来保持 Obsidian 里的排列顺序，`07自己`、`09附件` 沿用原名。【名字为要求，编号和这两个文件夹的保留为选定】

`00收集` 不再分子文件夹。`04博客` 下面允许为一组系列博客建子文件夹，比如订阅教程的 `原理版/`、`操作版/`。其他阶段文件夹不分子文件夹。

**R-STR-2 进阶段时新建，不移动。** 内容进入下一阶段时，作者新建一篇放进对应的文件夹，原文留在原处。新旧两篇可以用链接互相指向，但不强制。【要求】

**R-STR-3 不再有学习笔记这一类。** 学习后的体会写成思考。纯摘抄、转述或 AI 生成的总结只能放在 `00收集`，作者用自己的话改写后才算思考。【选定】

**R-STR-4 重写分类标准。** `docs/01系统/分类标准.md` 改写成上面的文件夹表加判断顺序，删掉 `02笔记`、`04技术`、`09归档`、`00收集/灵感` 相关的规则。判断顺序保留“先分清虚构还是真实”“出现真实人名或自我批判就放进 `07自己`”这两条。原来“放在 `00收集/灵感` 里默认算虚构”的规则随子文件夹一起取消，改为只看 front matter 和正文。Inbox Filer 插件继续读取这份文件。【选定】

**R-STR-5 迁移现有内容。** 按 R-STR-1 的“由哪里迁来”一列移动现有文件，所有指向被移动文件的双链和附件嵌入都要更新，迁移后不能有目标缺失。【要求】

### M2 内容清理

**R-CLN-1 删除笔记和归档。** 删除 `docs/02笔记` 和 `docs/09归档` 两个文件夹的全部内容。只被它们引用的 `09附件` 文件一起删除，被其他内容引用的附件保留。【要求，附件的处理为选定】

**R-CLN-2 处理失效链接。** 其他内容里指向被删页面的双链改成纯文字，保留原来显示的文字。【要求】截至 2026-10-26，公开内容里有 7 处这样的双链；`01系统`、`00收集`、`07自己` 里的也一并处理。

**R-CLN-3 删除转发脚本。** 删除 `scripts/setup.sh`，作者已经有专门的仓库放它。【要求】

### M3 发布范围

**R-PUB-1 只发布四个阶段。** 网站只为 `02思考`、`03初稿`、`04博客`、`05作品` 里的内容生成文章，每篇对应一个网页。【要求】

**R-PUB-2 不发布的内容打不开。** 不发布的内容不出现在构建产物里。公开文章指向它们的链接显示为纯文字。【要求，沿用 4.1.0 的行为】

**R-PUB-3 文章里的写法要能正常显示。** 公开文章里的双链、标题锚点和图片嵌入，在网页上要显示为可点的链接和图片。具体用什么方式做到，交给架构阶段。【要求】

**R-PUB-4 保留订阅教程的旧链接。** `/tech/subscribe-claude-quick/` 跳转到《如何订阅claude（纯操作版）》的新地址。其余旧网址不保证可用，旧的 Giscus 评论可以不跟到新网址。【要求】

**R-PUB-5 文章网址稳定。** 每篇文章的网址只取决于它自己的位置或 slug，不会因为别的文章增删而改变。【选定】

### M4 读者前端

**R-UI-1 单栏布局，没有侧边导航树。** 所有页面都是单栏，不出现 4.1.0 那棵左侧导航树。整体风格参考刘未鹏博客（mindhacks.cn）：以文字为主，装饰少。【要求“去掉侧边栏、参考刘未鹏”，具体布局为选定】
> 5.1.0 起，“参考刘未鹏、装饰少”这半句由 [R-VIS-1](#r-vis-1-视觉方向) 取代；单栏、没有侧边导航树不变。

**R-UI-2 顶部栏只有两项：首页和全部文章。** 点站名也回到首页。阶段不在顶部栏单独占一项，而是全部文章页上的筛选条件。不单独做“关于”页，作者的话放在首页。【首页与全部文章分开为要求，顶部栏内容为选定】

**R-UI-3 首页：作者的话加博客和作品。** 首页依次是：作者想对读者说的几段话（内容来自 `docs/index.md`，由作者自己写）；博客和作品混在一个列表里，按 `createdDate` 从新到旧排列，每项有标题、日期、阶段，写了 `description` 的再加一句简介。思考和初稿不出现在首页，列表末尾放一个“全部文章”的入口。首页不放评论区，也不放筛选。【要求】

**R-UI-4 全部文章。** 单独一页，按 `createdDate` 从新到旧列出所有公开文章，包括系列博客里的各篇，每项有标题、日期、阶段，属于系列的再标出系列名，写了 `description` 的再加简介。页面上可以按阶段（思考、初稿、博客、作品）和主题标签筛选，两种筛选可以同时用；筛选结果为空时给出提示。缺少 `createdDate` 的文章排在最后，构建只提示、不失败。【要求“单独的全部文章入口、按标签筛选”，阶段筛选和系列名为选定】

**R-UI-5 文章页。** 一篇文章一个网页，包括：标题、日期、阶段、主题标签、正文、公式、代码块一键复制、长文的目录、上一篇和下一篇，最后是 Giscus 评论区。【要求“保留”，目录和上下篇为选定】

**R-UI-6 系列博客能连着读。** `04博客` 子文件夹里的系列博客，在文章页上能看出它属于哪个系列，并能顺着系列读下一篇。首页只列 `04博客` 根目录下的文章，系列由根目录里的入口篇代表，比如《如何订阅claude》《如何订阅claude（纯操作版）》，子文件夹里的各篇不单独出现在首页，避免几十篇教程挤满首页。【选定】

## 6. 非功能需求

- **发布方式不变**：推送 `main` 后由 GitHub Actions 自动构建并发布到 GitHub Pages。【假设：架构阶段不改托管方式】

### 视觉

<a id="r-vis-1-视觉方向"></a>**R-VIS-1 视觉方向。** 明亮、可爱、带二次元气质，像轻小说封面：浅色模式是白底；背景垫大号淡色字做图形；标题用很粗的黑体；全站只有一个红橙色强调色；空白处点缀少量手画涂鸦（星星、音符、思考气泡、汗滴）；卡片和窗口用深色粗描边加实心投影。正文区域不放装饰，保证长文好读。【要求，具体取值以样稿为准】

**R-VIS-2 首页。** 依次是：对话气泡里的标题和作者的话；右侧垫两列淡色大字“想法”和“灵感”，对应想法线和写作线；黑圈里写公开文章总数；两张卡片画出两条线（想法线：思考 → 博客，写作线：初稿 → 作品），写各阶段篇数，点阶段名进入全部文章页并带上该阶段的筛选；然后是 R-UI-3 的博客和作品列表，按月分组，月份用大号数字。【选定】
- 气泡里的标题取 `docs/index.md` 正文的第一段，其余段落是作者的话；文件开头的一级标题（现在是“首页”）不显示。源文件不改。

**R-VIS-3 文章页。** 标题区依次是：阶段标签和日期（写于 `createdDate`，改过的再写 `updatedDate`）、很粗的标题、阶段的英文前缀、主题标签、“讲了什么”对话框（只在写了 `description` 时出现）；标题后面垫一个淡色大字；右上角黑圈写读完大约几分钟。正文结束处是一行涂鸦和“完”，上一篇、下一篇做成粗描边卡片，评论区放进带标题栏的小窗口。目录、系列导航、代码复制、公式按 R-UI-5、R-UI-6 照常保留，换成同一套视觉。【选定】
- 淡色大字取标题里第一个汉字或字母（跳过书名号、引号等标点；先去掉标题末尾的括号注释，如“（作品）”）；标题有四个字以上时，再垫一个取最后两个汉字的小一号大字。
- 读完时间按正文字数除以每分钟 400 字，四舍五入，最少 1 分钟。
- 正文开头那几行只写“写于 / 更新于 某日期”的引用块和标题区的日期重复，渲染时不显示；源文件不改。

**R-VIS-4 全部文章和 404。** 用同一套视觉：阶段筛选按钮按阶段着色，列表按月分组；404 页有一个大号淡色“404”和回首页、全部文章的入口。【选定】

**R-VIS-5 字体不依赖境外服务。** 读者大多在国内，页面不能从 Google Fonts 等境外字体服务加载字体。标题、大字和英文数字用的字体放在本站，只包含用得到的字；正文用读者系统自带的中文字体。【选定，理由：fonts.googleapis.com 在国内不稳定，字体加载失败时标题会退回系统字体，样稿的封面感就没了】

**R-VIS-6 涂鸦自己画。** 星星、音符等涂鸦用代码画成 SVG，不使用任何动漫角色、封面或他人插画。【选定】

**R-VIS-7 深色模式。** 跟随系统设置，不做手动切换（沿用第 8 节的默认值）。深色下底色是深灰紫，淡色大字和卡片照样看得出层次，文字对比度足够阅读。【选定】

### 非功能

- 375px 宽度下所有页面仍不能横向滚动；大字可以被裁掉，但不能撑宽页面。
- 系统设置了“减少动态效果”时，卡片的悬停动画关掉。
- 没有 JS 时页面照常可读（沿用 T2 的做法）。
- 一个页面首次加载的字体文件合计不超过 300 KB（【假设】由 V0 验证）。
