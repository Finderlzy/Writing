# 需求：按阶段管理内容，网站只为读者重做（目标版本 5.0.0）

> 写于 2026-10-26。基线是 4.1.0（见 [DEVELOPMENT.md](DEVELOPMENT.md)）。术语以根目录 [CONTEXT.md](../CONTEXT.md) 为准，本文不重复定义。
>
> 标注：【要求】作者明确提出；【选定】作者授权后由 Agent 选定，可以推翻；【假设】待验证；【待定】未决定。

## 1. 目标与范围

### 为什么改

这个项目最早是为了在多台设备上读自己在 Obsidian 里写的东西。订阅教程带来大量读者以后，网站为了照顾观感一点点加功能，结果自用和读者两个目的混在一个文档风格的站点里，分类和界面都越来越乱。

这一版把两个目的分开：

- **自用**：作者通过 GitHub 同步整个 Obsidian 仓库，在其他设备上阅读全部内容，包括不公开的部分。网站不再承担这个用途。【要求】
- **读者**：网站只展示思考、初稿、文章和作品，按个人博客的样子从头设计。【要求】

### 成功标准

- 作者拿到一篇新内容时，只看 `分类标准.md` 就能确定它属于哪个阶段、放进哪个文件夹。
- 读者在手机上打开首页，先看到文章和作品；从首页出发，点两次以内能读到任意一篇博文。
- 不公开的内容在网站上打不开。
- 除了作者明确要求删除的内容，原有的源文件一篇不少。

### 首期范围

1. 按阶段重新定义文件夹和分类标准。
2. 清理不再需要的内容：`02笔记`、`09归档`、`scripts/setup.sh`。
3. 重新划定发布范围。
4. 重做读者前端：首页、全部博文、博文页。

### 非目标

- 用网站做自用阅读，或者给网站加登录、密码之类的访问控制。
- 把 `07自己` 移出公开仓库。作者接受有人翻源码读到它。【要求】
- 保留旧网址。只有 `/tech/subscribe-claude-quick/` 例外，见 R-PUB-4。
- 访问统计和站内搜索。【选定】
- 改写已有内容里的 Obsidian 语法。今后作者会少用复杂语法，但不要求回头修改旧文。【要求】
- 规定生成器、主题和转换层怎么实现。这些交给架构阶段；现有的 Obsidian 转换层允许删除。【要求】

## 3. 三级边界

**Always**

- 构建过程只读取 `docs/`，不写入、不删除；转换和生成都在别处进行。
- 除了第 5 节明确要删的，任何改动都不能删掉 `docs/` 里的内容文件。
- 改变目录或发布范围时，同步更新 `docs/01系统/分类标准.md` 和项目 `AGENTS.md` 的“项目说明”。
- 手机宽度（375px）下，页面不能出现横向滚动。

**Ask first**

- 删除第 5 节以外的任何内容文件或附件。
- 修改 `README.md`。README 由作者本人维护，过时的说明列给作者，由作者决定怎么改。
- 改动 `docs/.obsidian/` 里的插件配置，包括 Inbox Filer 和 Obsidian Git。
- 增加第三方服务或付费依赖。

**Never**

- 发布想法、灵感、自己和规则这四类内容。
- 为了让构建或测试通过而删除内容文件、跳过检查。
- 做首期非目标里列出的功能。

## 4. 用户场景

**S1 作者从想法写到文章。** 作者在 `00收集` 记下一个想法。之后用自己的话写了一篇思考，新建在 `03思考`。几个月后，作者把几篇思考整合成一篇文章，新建在 `04文章`。原来的想法和思考都留在原处，不移动；思考和文章各自成为一篇博文。

**S2 读者从教程进站。** 读者点开视频里的旧链接 `/tech/subscribe-claude-quick/`，被跳转到这篇文章的新地址。读完以后，读者点“全部博文”，按“二次元”标签筛选，打开一篇思考。

**S3 作者在手机上看私人内容。** 作者在手机上通过 GitHub 同步打开 `07自己` 里的一篇。网站上没有这篇，用猜到的网址访问也打不开。

## 5. 功能需求

### M1 内容结构

**R-STR-1 文件夹表示阶段。** 每篇内容的阶段只由它所在的文件夹决定；标签只表示主题，不表示阶段。【要求】对应关系如下：

| 文件夹 | 内容 | 是否发布 |
| --- | --- | --- |
| `00收集` | 想法 | 否 |
| `00收集/灵感` | 灵感 | 否 |
| `01系统` | 规则 | 否【选定】 |
| `03思考` | 思考 | 是 |
| `03思考/初稿` | 初稿 | 是 |
| `04文章`（由 `04技术` 改名） | 文章 | 是【选定】 |
| `05作品` | 作品 | 是 |
| `07自己` | 自己 | 否 |
| `09附件` | 图片等附件，只有公开博文用到的才发布 | — |

`04文章` 下面允许为一组系列文章建子文件夹，比如订阅教程的 `原理版/`、`操作版/`。

**R-STR-2 进阶段时新建，不移动。** 内容进入下一阶段时，作者新建一篇放进对应的文件夹，原文留在原处。新文与原文之间可以用链接互相指向，但不强制。【要求】

**R-STR-3 不再有学习笔记这一类。** 学习后的体会写成思考。纯摘抄、转述或 AI 生成的总结只能作为想法，放在 `00收集`，作者用自己的话改写后才算思考。【选定】

**R-STR-4 重写分类标准。** `docs/01系统/分类标准.md` 改写为两条线六个阶段，加上自己和规则两类，删掉 `02笔记`、`04技术`、`09归档` 相关的规则。拿不准时的判断顺序保留“先分清虚构还是真实”“出现真实人名或自我批判就放进 `07自己`”这两条。Inbox Filer 插件继续读取这份文件。【选定】

### M2 内容清理

**R-CLN-1 删除笔记和归档。** 删除 `docs/02笔记` 和 `docs/09归档` 两个文件夹的全部内容。只被它们引用的 `09附件` 文件一起删除。被其他内容引用的附件保留。【要求，附件的处理为选定】

**R-CLN-2 处理失效链接。** 其他内容里指向被删页面的双链改成纯文字，保留原来显示的文字。【要求】截至 2026-10-26，公开内容里有 7 处这样的双链，`01系统`、`00收集`、`07自己` 里的也一并处理。

**R-CLN-3 删除转发脚本。** 删除 `scripts/setup.sh`，作者已经有专门的仓库放它。【要求】

**R-CLN-4 改名后修正链接。** `04技术` 改名为 `04文章` 以后，所有指向它的双链都要能找到目标，不能出现目标缺失。

### M3 发布范围

**R-PUB-1 只发布四个阶段。** 网站只为 `03思考`、`03思考/初稿`、`04文章`、`05作品` 里的内容生成博文，每篇对应一个网页。【要求】

**R-PUB-2 不发布的内容打不开。** 不发布的内容不出现在构建产物里。公开博文指向它们的链接显示为纯文字。【要求，沿用 4.1.0 的行为】

**R-PUB-3 博文内的写法要能正常显示。** 已发布博文里的双链、标题锚点和图片嵌入，在网页上要显示为可点的链接和图片。具体用什么方式做到，交给架构阶段。【要求】

**R-PUB-4 保留订阅教程的旧链接。** `/tech/subscribe-claude-quick/` 跳转到《如何订阅claude（纯操作版）》的新地址。其余旧网址不保证可用，旧的 Giscus 评论可以不跟到新网址。【要求】

**R-PUB-5 博文网址稳定。** 每篇博文的网址只取决于它自己的位置或 slug，不会因为别的文章增删而改变。【选定】

### M4 读者前端

**R-UI-1 单栏布局，没有侧边导航树。** 所有页面都是单栏，不出现 4.1.0 那棵左侧导航树。整体风格参考刘未鹏博客（mindhacks.cn）：以文字为主，装饰少。【要求“去掉侧边栏、参考刘未鹏”，具体布局为选定】

**R-UI-2 顶部栏只有三项：首页、全部博文、关于。** 阶段不在顶部栏单独占一项，而是作为全部博文页的筛选条件，这样顶部栏不会和全部博文重复。“关于”放现在首页上那段自我介绍。【选定】

**R-UI-3 首页先展示文章和作品。** 首页依次是：一两句自我介绍；文章和作品的列表，每项有标题、日期，写了 `description` 的再加一句简介；最后是“全部博文”的入口。思考和初稿不直接列在首页。【要求“优先放文章和作品”，具体编排为选定】

**R-UI-4 全部博文可以筛选。** 全部博文页按 `createdDate` 从新到旧列出所有博文，每项有标题、日期、阶段，写了 `description` 的再加简介。页面上可以按阶段（思考、初稿、文章、作品）和主题标签筛选，两种筛选可以同时用；筛选结果为空时给出提示。缺少 `createdDate` 的博文排在最后，构建只提示、不失败。【要求“全部入口加标签筛选”，阶段筛选为选定】

**R-UI-5 博文页。** 一篇博文一个网页，包括：标题、日期、阶段、主题标签、正文、公式、代码块一键复制、长文的目录、上一篇和下一篇，最后是 Giscus 评论区。首页和全部博文页不放评论区。【要求“保留”，目录和上下篇为选定】

**R-UI-6 系列文章能连着读。** `04文章` 子文件夹里的系列文章，在博文页上能看出它属于哪个系列，并能顺着系列读下一篇。【选定】

## 6. 非功能需求

- **手机优先**：在 375px 宽度下，所有页面不出现横向滚动，正文不用缩放就能读。
- **构建失败要说清楚**：内容有问题导致构建失败时，指出是哪个文件、哪一行。【沿用 4.1.0】
- **发布方式不变**：推送 `main` 后由 GitHub Actions 自动构建并发布到 GitHub Pages。【假设：架构阶段不改托管方式】
