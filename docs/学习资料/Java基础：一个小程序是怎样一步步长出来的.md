目前学到的 Java 知识看起来很多：字面量、数据类型、运算符、Scanner、数组、方法……但其实它们不是互相独立的。

可以先给自己一个任务：

> **写一个成绩分析程序：让用户输入若干学生的成绩，然后输出所有成绩、总分和平均分。**

如果现在从零开始写，会不断遇到问题。而我们目前学到的这些知识，恰好就是一个个解决这些问题的工具。

整条学习路线其实是：

```text
程序要处理数据
    ↓
数据需要保存和区分类型
    ↓
数据需要计算
    ↓
程序需要决定“做不做、做几次”
    ↓
数据不能永远写死，需要用户输入
    ↓
学生越来越多，一个变量装不下
    ↓
出现数组
    ↓
程序越来越长，需要拆分任务
    ↓
出现方法
    ↓
最终组成完整的小程序
```

---

## 一、程序首先需要有东西可以处理：数据

假设我们现在只想保存一个学生的成绩：

```java
int score = 90;
```

这里其实已经出现了三个东西：

```text
90        → 数据本身
int       → 这个数据是什么类型
score     → 我们以后用什么名字找到它
```

其中直接写在代码里的 `90`，Java 称为**字面量**。

目前接触过的字面量包括整数、小数、字符串、字符、布尔值和 `null`。

例如：

```java
90
95.5
"hello"
'A'
true
null
```

但只有数据还不够。程序运行过程中，我们经常需要把数据保存下来，于是有了**变量**：

```java
int score = 90;
```

可以暂时理解为：

> **字面量是数据，变量负责保存数据，数据类型负责规定这个变量能够保存什么样的数据。**

所以最底层的一条关系是：

```text
数据
 ↓
数据类型描述它
 ↓
变量保存它
```

---

## 二、有了数据以后，程序就要开始处理数据

只把成绩保存下来没有意义，我们最终还要计算：

```text
总分
平均分
是否及格
```

于是需要各种运算符。

例如：

```java
sum = a + b;
average = sum / num;
score >= 60
```

程序开始从“保存数据”变成了“处理数据”。

但这里马上又会遇到一个问题。

假设：

```java
int sum = 271;
int num = 3;
```

我们想算平均分：

```java
double average = sum / num;
```

这里涉及了不同的数据类型。

于是便出现了我们学习过的**类型转换**。

你的笔记把它分成两种：

```text
隐式转换
强制类型转换
```

当不同数值类型参与运算时，会发生相应的类型转换；而把范围较大的类型主动转换为较小类型时，可以写：

```java
double a = 33.11;
int b = (int) a;
```

这种写法可能损失数据。

成绩程序里也实际使用了：

```java
double average = (double) sum / arr.length;
```

这里可以看出：**类型并不是给变量贴个标签就结束了，它还会影响后面的运算结果。**

所以知识链又向前走了一步：

```text
数据
 ↓
变量保存
 ↓
数据类型
 ↓
运算
 ↓
不同类型参与运算
 ↓
类型转换
```

---

## 三、同一个 `+`，处理不同数据时也可能不同

刚开始看到：

```java
1 + 2
```

很自然会认为 `+` 就是数学加法。

但后来我们又写出了：

```java
System.out.println("平均分为：" + average);
```

这里显然没有在计算“平均分为：”加一个数字。

因为当字符串参与 `+` 运算时，可以进行**字符串拼接**。你的笔记中记录了：

```java
1 + "afd"
```

会得到：

```text
"1afd"
```

因此运算符不能脱离数据类型理解。

应该一起看：

```text
数据是什么类型
        ↓
运算符作用在什么数据上
        ↓
Java 决定这次运算意味着什么
```

这也是为什么学习数据类型不是为了单纯背 `int`、`double`，而是因为**类型会影响程序怎样解释数据和运算。**

---

# 四、可是程序不能每次都做完全一样的事情

现在我们已经可以保存和计算数据了。

但成绩程序还有两个明显的问题。

比如：

> 成绩低于 60 分怎么办？

程序需要根据不同情况选择不同操作，于是需要 `if`。

再比如：

> 如果有 30 个学生，难道把输入语句写 30 次吗？

当然不能。

于是需要循环。

```java
for (int i = 0; i < 30; i++) {
    // 重复执行
}
```

所以控制语句解决的是另一个层面的问题：

前面的知识主要在回答：

> **数据是什么？数据怎么算？**

而 `if` 和循环开始回答：

> **代码什么时候执行？执行多少次？**

于是一个程序现在有了两个基本部分：

```text
数据
+
控制数据处理过程的流程
```

---

## 五、逻辑运算让判断条件可以组合

实际判断往往不会只有一个条件。

例如以后可能会写：

```java
score >= 0 && score <= 100
```

我们需要同时判断：

```text
成绩不能小于 0
并且
成绩不能大于 100
```

于是需要逻辑运算。

目前接触过：

```java
&
|
!
^
```

以及带有短路功能的：

```java
&&
||
```

你的笔记中把 `&&`、`||` 称为**短路逻辑运算符**。

它们解决的仍然是同一个问题：

> **程序到底应该在什么条件下继续执行？**

所以它应该放在流程控制这里理解，而不是孤立地背两个符号。

---

# 六、现在程序能计算了，但数据还是程序员提前写进去的

目前可能写成：

```java
int score = 90;
```

问题来了：

> 总不能每换一个学生，就重新修改源代码吧？

我们希望程序运行之后，由用户告诉程序成绩是多少。

于是数据来源需要发生变化：

```text
以前：
程序员 → 源代码 → 数据

现在：
用户 → 键盘 → 程序 → 数据
```

这时就出现了 `Scanner`。

你的笔记记录了它最基本的三个步骤：

先导入：

```java
import java.util.Scanner;
```

创建 Scanner：

```java
Scanner sc = new Scanner(System.in);
```

然后读取输入：

```java
int score = sc.nextInt();
```

于是：

```java
int score = 90;
```

变成：

```java
int score = sc.nextInt();
```

从这一刻开始，程序处理的不再只是程序员提前写好的数据，而是**运行过程中才得到的数据**。

---

# 七、一个变量可以保存一个成绩，但我要保存很多学生

接下来又遇到新问题。

如果只有一个学生：

```java
int score;
```

没有问题。

三个学生还能勉强：

```java
int score1;
int score2;
int score3;
```

但如果用户告诉我们：

```text
这个班有 50 个学生。
```

总不能提前写：

```java
score1
score2
score3
...
score50
```

于是需要一个东西：

> **用一个变量管理一批同类型的数据。**

这就是数组。

```java
int[] studentsScore;
```

你的笔记记录了两种初始化方式：

```java
int[] arr = {1, 2, 3};
```

以及：

```java
int[] arr = new int[3];
```

Java 分别称为静态初始化和动态初始化。

---

## 八、Scanner 和数组结合以后，程序突然完整了很多

现在我们可以先问：

```java
int studentsNum = sc.nextInt();
```

得到学生人数。

然后直接：

```java
int[] studentsScore = new int[studentsNum];
```

这个写法正是我们之前讨论过的地方。

学生人数并不需要在写代码的时候提前知道。

可以：

```text
用户输入人数
    ↓
studentsNum 得到这个数字
    ↓
按照 studentsNum 创建数组
```

你最后的程序就是这样写的：

```java
int studentsNum = sc.nextInt();

int[] studentsScore = new int[studentsNum];
```

接下来数组又天然可以和循环组合：

```java
for (int i = 0; i < studentsScore.length; i++) {
    studentsScore[i] = sc.nextInt();
}
```

于是之前学习过的几个东西第一次真正连在了一起：

```text
Scanner
   ↓
获得学生人数
   ↓
创建数组
   ↓
for 循环
   ↓
逐个输入
   ↓
数组保存所有成绩
```

这比单独记住“Scanner 怎么写”和“数组怎么写”重要得多。

---

# 九、但是新的问题又出现了：代码越来越长

现在 `main` 里面已经需要完成：

```text
读取学生人数
创建数组
录入所有成绩
输出所有成绩
计算总分
计算平均分
```

如果以后再增加：

```text
最高分
最低分
及格人数
排序
查询某个学生
```

所有代码都塞进 `main`，很快就会乱掉。

于是我们需要把一个大任务拆成若干小任务。

这就是**方法**开始真正有意义的地方。

你的笔记把方法理解为函数，并记录了基本定义形式：

```java
public static 返回值类型 方法名(参数) {
    ...
}
```

现在不要只把它理解成一段需要背的语法。

它真正解决的问题是：

> **一个程序里的任务越来越多，怎样把不同任务分别组织起来？**

于是：

```text
完成整个成绩分析
```

可以拆成：

```text
main
 ├─ 获取数据
 ├─ all：输出所有成绩
 └─ sumAndAverage：计算总分和平均分
```

这就是你最后程序的结构。

# 十、参数解决“方法怎么拿到数据”的问题

我们把任务拆进方法以后，又会马上产生问题：

> `studentsScore` 是在 `main` 里面得到的，别的方法怎么知道这些成绩？

于是出现了**参数**。

例如：

```java
public static void all(int[] arr)
```

调用：

```java
all(studentsScore);
```

可以理解成：

```text
main 手里有 studentsScore
        ↓
调用 all
        ↓
把 studentsScore 交给 all
        ↓
all 用自己的参数 arr 接住
```

于是方法不是一个孤立的小盒子。

不同方法可以通过参数传递数据。

---

# 十一、返回值又解决了反方向的问题

参数解决：

> **调用者怎样把数据交给方法？**

接下来还会遇到反方向的问题：

> **方法算出了一个结果，怎样把结果交还给调用者？**

于是有了返回值。

也就是说，理解参数和返回值时可以把它们放在同一张图里：

```text
调用者
  │
  │ 参数
  ↓
方法
  │
  │ return
  ↓
调用者
```

参数负责把东西**送进去**。

返回值负责把结果**带回来**。

至于 `void`，在前面的讨论里已经纠正过一个容易产生的误解：它不是“返回给控制台”，而是表示这个方法**没有返回值交给调用者**。

例如你的：

```java
public static void all(int[] arr)
```

负责直接打印成绩，因此当前程序没有要求它再返回一个结果。

---

# 十二、`public static` 暂时不用当成一句咒语

学习方法时很容易形成：

```java
public static
```

必须写在每个方法前面的感觉。

但你的方法笔记已经记录了一个更好的理解方向：

```text
public → 决定谁可以使用这个方法
static → 决定方法属于类还是对象
```

目前还没有正式学习面向对象，因此不必现在就把它们全部展开。

现阶段只需要知道：

> **它们各自有作用，不是“定义函数固定要写的四个单词”。**

以后学习类和对象以后，再回来理解 `static`，会自然很多。

# 十三、现在回头看完整程序

你最后写出的代码已经不只是“练习数组”或者“练习方法”了，而是目前这些知识第一次真正组合在一起。

它的运行过程实际上是：

```text
程序启动
   ↓
Scanner 等待用户输入
   ↓
得到学生人数
   ↓
按照人数创建数组
   ↓
for 循环多次读取成绩
   ↓
成绩全部进入数组
   ↓
把数组传给 all()
   ↓
遍历并输出所有成绩
   ↓
把数组传给 sumAndAverage()
   ↓
循环求和
   ↓
类型转换后计算平均值
   ↓
输出结果
```

这条流程里，已经几乎能找到目前学过的所有核心知识。

# 十四、真正应该记住的不是十几个知识点

如果把目前的内容拆开背，会变成：

```text
字面量
类型转换
字符串
逻辑运算符
Scanner
数组
方法
参数
返回值
……
```

看起来非常杂乱。

但它们其实是在不断解决程序发展过程中产生的新问题：

```text
我要处理信息
↓
需要数据

我要保存数据
↓
变量和数据类型

我要改变数据
↓
运算

不同类型的数据一起运算怎么办
↓
类型转换

程序不能每次都做一样的事
↓
判断和循环

判断越来越复杂
↓
逻辑运算

数据不能永远写死
↓
Scanner

一个变量装不下几十个成绩
↓
数组

数组里的几十个元素需要逐个处理
↓
循环 + 数组

代码越来越长
↓
方法

方法需要拿到外面的数据
↓
参数

方法需要把结果交回来
↓
返回值
```

最终才得到：

```text
一个完整的小程序
```

所以现在这个阶段真正建立起来的，不只是一些 Java 语法，而是一个很基础但很重要的程序结构：

```text
输入数据
   ↓
保存数据
   ↓
控制处理过程
   ↓
计算、修改数据
   ↓
把不同任务拆开组织
   ↓
输出结果
```

以后程序会越来越复杂，但很多程序最底层依然能看到这条链。

## 当前阶段的落点

现在已经到了一个比较自然的分界线。

之前更多是在学：

> **“Java 的某个语法怎么写？”**

而完成成绩分析程序之后，可以开始逐渐进入：

> **“我想完成一个功能，需要把哪些语法组合起来？”**

这两种学习状态并不一样。

前者是在学语言的零件。

后者开始是在**用这些零件做东西**。

接下来继续学习新的 Java 知识时，也可以一直问一句：

> **“如果没有这个东西，我现在到底会遇到什么问题？”**

只要这个问题能回答出来，新知识通常就不会变成孤零零的一条语法。
