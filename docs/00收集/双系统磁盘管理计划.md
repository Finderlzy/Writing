## 先说整体思路

整理的目标是让**每个盘只有一个明确的用途**。以后新东西该放哪里，不用想就知道。

你的硬盘里 Windows 能看到三个盘，加上要给 Ubuntu 切的空间，我建议这样分：

|盘|大小|用途|谁在用|
|---|---|---|---|
|C|199G|Windows 系统 + 只能装 C 盘的软件|Windows|
|E|201G|Windows 的软件、游戏、开发环境|Windows|
|D（重建）|约 288G|**共享数据**：图片、视频、模型、下载|两边共用|
|新 ext4 分区|150G|Ubuntu 的代码、conda 环境|Ubuntu|

**格式化 D 盘最合适。** 原因有两个：

- D 本来就要当共享盘，正好借这个机会清空重来
- 删掉 D 盘再重建，比「压缩卷」更干净。压缩卷有时会被系统文件卡住，切不出想要的大小

## 每个盘里怎么放

**E 盘（Windows 专用）**

```
E:\
├─ Software\     软件安装目录（装软件时手动选这里）
├─ Games\        游戏（无畏契约等）
└─ Dev\          Windows 开发用
   ├─ Projects\  代码仓库（和 Ubuntu 通过 GitHub 同步）
   └─ Envs\      conda / Python 虚拟环境、JDK、Node
```

**D 盘（共享）**

```
D:\
├─ Media\
│  ├─ Pictures\
│  └─ Videos\
├─ Models\       模型权重（HuggingFace 缓存也设到这里）
├─ Datasets\     数据集、训练素材（比如声音克隆的音频）
├─ Downloads\    两个系统的浏览器都下载到这里
├─ Notes\        Obsidian 笔记库（两边的 Obsidian 打开同一个文件夹）
└─ Backups\
```

规则只有三条：

1. **D 盘只放数据，不放代码和环境。** 原因我在第一条回复里讲过：NTFS 对 Linux 的权限、软链接都不友好
2. **文件夹名用英文、不带空格。** Linux 终端里打路径会方便很多
3. **新东西先进 `Downloads`，定期分拣。** 分拣到 Media、Models 等对应的文件夹里，不要让 Downloads 越堆越乱

## 操作顺序

**第 1 步：盘点 D 盘**  
看一下 D 盘里有哪些要留，分成三类：

- 能重新下载的（软件、游戏、模型）→ 直接删掉
- 只有 Windows 用的软件或游戏 → 卸载，以后装到 E 盘
- 真正需要保留的（自己的照片、文档、作品）→ 先复制到别处

**第 2 步：找地方暂存要保留的东西**  
E 盘现在只剩约 34G，Ubuntu 只剩约 7G。如果要保留的东西放得下，就暂存到这里。  
如果放不下，**就不要格式化**，改成在原地整理 D 盘，然后用压缩卷切出 150G。效果一样，只是多费点功夫。

**第 3 步：重建 D 盘**（Windows 磁盘管理里操作）

1. 右键 D 盘 → **删除卷**。整个 D 会变成 438G 的「未分配」空间
2. 右键这块未分配空间 → **新建简单卷**，大小填 `294912`（288G），格式选 NTFS，盘符选 D，卷标写 `Shared`
3. 新卷会建在这块空间的前面，剩下的 150G 自然留在后面，**正好紧挨着 Ubuntu**。这块空间保持未分配，不要动

**第 4 步：Windows 的设置**

- 把「下载」「图片」「视频」这几个系统文件夹搬到 D 盘：在资源管理器里右键对应文件夹 → 属性 → **位置** → 移动，选 D 盘对应的文件夹
- 设置环境变量 `HF_HOME=D:\Models\huggingface`。设置路径：在开始菜单搜「环境变量」→ 用户变量 → 新建
- 确认快速启动已经关掉

**第 5 步：回到 Ubuntu**  
做完这些后，Ubuntu 这边还有两件事：把 D 盘挂载到 `/mnt/shared`，把那 150G 格式化成 ext4 挂到 `/data`。到时候我带你做。


---
你的 D、E 和我上一条假设的正好反过来。那就**不用格式化了**，把两个盘的角色对调一下就行：

|盘|现在放的|以后的角色|
|---|---|---|
|D|软件、游戏、开发工具|**Windows 专用**：软件、游戏、开发工具、Windows 下的代码|
|E|各种数据|**共享数据盘**：两个系统共用|

D 盘只需要从末尾压缩出 150G 给 Ubuntu。如果压缩时被系统文件卡住、切不出这么多，再考虑格式化 D 重装软件。你说能接受重新下载，这就是兜底方案。

## 默认的数据分类方式好不好？

**可以用，而且对双系统特别合适，但不能只靠它。**

**好处：Ubuntu 也有一模一样的五个文件夹。**  
你截图左边栏里的文档、音乐、图片、视频、下载，就是 Ubuntu 的默认文件夹，和 Windows 一一对应。以后可以让两个系统的这五个文件夹都指向 E 盘的同一个位置。这样无论在哪个系统里点「图片」，看到的都是同一批图片。

**缺点：它按「文件类型」分类，不按「用途」分类。**  
图片、视频这类媒体很好分，但很多东西放不进去：

- 学校的资料是一门课的，里面有 PDF、代码、图片，该放哪？
- 模型、数据集算哪一类？
- 最后什么都往「文档」里塞，「文档」就会变成新的杂物间

所以我建议的规则是：**媒体文件按类型分，其余按用途分。**

## E 盘的新结构

```
E:\
├─ 下载\  图片\  视频\  音乐\  文档\    ← 保留默认五个，只放对应类型的东西
├─ School\      学校的东西，按学期/课程分
├─ Books\       现在的「各种书」
├─ Models\      模型权重（llama.cpp 的模型、HuggingFace 缓存）
├─ Datasets\    数据集、训练素材
├─ Wallpaper\
├─ Backups\
└─ 密码.kdbx
```

整理时要从 E 盘**搬走**的东西：

- **WorkSpace**：代码放进 D 盘（比如 `D:\Dev\Projects`），留给 Windows 开发用。Ubuntu 用自己 `/data` 里的那一份，两边通过 GitHub 同步
- **学校文件夹里的软件和开发工具**：搬到 D 盘。School 里只留资料和作业
- **llama.cpp、dafeiyu-demucs** 这类程序本体：搬到 D 盘，它们下载的模型文件放 `E:\Models`
- **「好东西」**：你自己看看里面是什么，按上面的类别分进去，不要保留一个叫「好东西」的杂物文件夹

顺带一提，`密码.kdbx` 是 KeePass 的密码库文件。Ubuntu 上装 **KeePassXC** 就能打开同一个文件，两边共用一个密码库。这个文件很重要，记得在 Backups 或云盘里另外存一份。

## 接下来

1. **在 Windows 里整理 E 盘**：按上面的结构搬文件。这一步在 Windows 里做比较顺手
2. **压缩 D 盘**：磁盘管理 → 右键 D → 压缩卷 → 填 `153600`
3. **回到 Ubuntu**：把 E 盘挂载好，让 Ubuntu 的五个默认文件夹指向 E 盘，再把那 150G 格式化成 `/data`

第 2 步压缩完，把磁盘管理的截图发给我。尤其是如果切出来的空间不到 150G，我们再决定要不要格式化 D 盘。


---
D 盘的思路和 E 盘不一样：**E 盘可以随便搬，D 盘不能。**

装好的软件在注册表、快捷方式、环境变量里都记着自己的路径，直接剪切到别的文件夹，软件就打不开了。所以 D 盘的原则是：**已装的软件不动，以后新装的按新结构放；只整理那些可以随便挪的东西。**

## 先认识一下 D 盘里的文件夹

**系统和软件自动建的，不要碰：**

- `$RECYCLE.BIN`、`System Volume Information`、`Config.Msi`、`DumpStack.log.tmp`：Windows 系统文件
- `WindowsApps`、`WpSystem`：微软商店应用装在 D 盘时自动生成的
- `ProgramData`、`Users`：一般是某些软件建的，删了可能出问题
- `DeliveryOptimization`：Windows 更新的缓存
- `ASUS`：华硕自带软件

**正常的软件目录，保留：**

- `Program Files`、`Program Files (x86)`：软件安装的标准位置，以后装软件继续装这里就行
- `WeGameApps`：WeGame 的游戏库
- `Xilinx`：Vivado 这类工具体积很大，对路径很敏感，原地不动

**可以整理的：**  
`DevTools`、`DevCaches`、`.pnpm-store`、`BaiduNetdiskDownload`、`QuarkDownload`、`Ubuntu-Videos`、`MineradioCache`、`Temp`

## D 盘的新结构

```
D:\
├─ Program Files\         ← 图形界面软件（保持现状）
├─ Program Files (x86)\
├─ Games\                 ← 以后新装的游戏
├─ WeGameApps\            ← 已有的，不动
├─ Xilinx\                ← 已有的，不动
├─ Dev\                   ← Windows 开发的一切
│  ├─ Tools\    命令行开发工具：JDK、Maven、Git、llama.cpp、demucs…（原 DevTools）
│  ├─ Envs\     conda / Python 虚拟环境
│  ├─ Caches\   包管理器缓存：pnpm、npm、pip、Maven（原 DevCaches + .pnpm-store）
│  └─ Projects\ 代码仓库（从 E:\WorkSpace 搬来）
├─ Drivers\               ← 原 ASUS-Driver-Backup，重装系统时有用
└─ 系统文件夹们（不动）
```

## 具体怎么搬

**1. 下载类文件夹 → 搬到 E 盘**

- `BaiduNetdiskDownload`、`QuarkDownload`：把里面的文件分拣到 E 盘对应的文件夹，然后在百度网盘和夸克的设置里，把下载位置改成 `E:\下载`
- `Ubuntu-Videos`：搬到 `E:\视频`

**2. 命令行工具 → `Dev\Tools`**  
这类工具大多是解压即用的，可以挪，但挪完要更新环境变量。

**环境变量 `Path`** 是 Windows 用来记录「去哪里找命令」的一张清单。比如你在终端敲 `java`，系统就是靠它找到 JDK 的。工具挪了位置，就要把 Path 里的旧路径改成新路径，否则命令会找不到。

所以建议**一个一个挪**：挪一个，改 Path，在终端里测试命令能用，再挪下一个。

**3. 缓存 → `Dev\Caches`**  
缓存的位置不能只靠搬文件夹，要通过工具自己的命令修改。比如 pnpm：

```
pnpm config set store-dir D:\Dev\Caches\pnpm-store
```

改完后，旧的 `.pnpm-store` 可以直接删掉，下次用到时会自动重新下载。

**4. 代码 → `Dev\Projects`**  
`E:\WorkSpace` 里的仓库整个搬过来就行。搬之前先确认每个仓库都已经 push 到 GitHub。

## 关于压缩 D 盘

D 盘装的都是软件，压缩时比较容易被不能移动的文件卡住，切不出 150G。

如果真的被卡住，你有两条路：

- 少切一点，比如 100G
- 清空 D 盘重建，然后重装软件。你说能接受重新下载，这条路也走得通。顺便按上面的新结构从零开始装，D 盘会比现在干净很多
