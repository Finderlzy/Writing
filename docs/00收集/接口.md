经过多年的发展，互联网行业已经有了许许多多的工具。在我们自己开发项目的时候，难免会想直接使用已有的工具来完善我们自己的项目。一般而言，工具方会提供一种叫作**接口**的服务，来给我们使用他们做的工具。

什么是接口？它是用来干嘛的？

接口就是提供服务方开的一个小窗户，你向他提供他需要的信息，他就会返回给你你想要的东西。比如买蜜雪冰城，前台肯定会问你一些问题（参数），“你要喝什么？”、“热的还是冰的？”、“几分糖？”、“要加小料吗？”......当你回答完这些问题，店员就会去做你要的奶茶。回到接口这边，你需要向提供服务方传入一些参数，这样提供服务方才能为你服务。

一个完整的接口由四部分组成，一个是请求方法，另一个是路径，还有一个是参数，最后一个是返回结果。前面已经讲过参数了，那什么是请求方法？简单来说就是**怎么把参数给到服务提供方**，常见的有 `GET` 和 `POST` 。还是用买奶茶举例，`GET` 给我的感觉就是一下子把全部的信息都告诉服务提供方；而 `POST` 就比较优雅，拿纸条工工整整地写。路径是什么？就是选择你要用的服务。这里不能拿买奶茶举例子了，可以拿饭店。饭店可以提供两种服务，一个是直接吃，另一个是代加工。这就是选择不同的服务。

我认为接口的作用有三个，一个是规范作用。如果没有接口，每个人向服务提供方传参数的时候传的都是不一样的，服务提供方还得一个个问，或者猜。有了接口，服务提供方一看就知道对方想要什么，效率就高了很多，这也是我认为的接口的第二个作用。最后一个作用，体现了计算机领域的一个重要思想——封装。简单来说，就是你不需要知道这个服务是如何做到的，你只需要知道，你把这几个参数传进去，你就能得到一个东西。你不需要知道奶茶是什么做的，你只需要知道，你说一下你要什么东西，把钱付给人家，你就能得到一杯蜜雪冰城柠檬水。

现在我们明白了接口是什么、怎么用，然后我们会面临一个问题：我怎么知道服务提供方有哪些服务？那些服务的接口是什么？

一般是是去 `README` 里面找，或者去源码里面找名字里面有 `api` 的文件。如果该项目的接口框架是 `FastAPI`，则接口的参数往往在 `/docs` 里面。

如我最近在玩的 `GPT-SoVITS` 项目，我先通过寻找 `.py` 文件，找到了接口服务的程序（下面的 `api.py`和 `api_v2.py`。

回看一下整个过程。首先是找到开源项目的接口提供程序，并运行。如果是由 `FastAPI` 框架写出来的，就可以直接去 `/docs` 查看接口的参数。然后把请求写好之后，用浏览器（或终端的 curl）把请求发给服务。

为什么这个服务是 Web 服务？**Web 服务的意思是：它用 HTTP 这套"说话规矩"、通过网址来接收请求和返回结果。** 上面那长长的 `http://...` 就是按 HTTP 规矩写的请求。至于**为什么要做成 Web 服务**，这才是关键：GSV 是 Python 写的。如果它不开接口，你想用它就只能也写 Python、把它的代码直接引进来。但做成 Web 服务之后，**谁都能用**——浏览器能用，curl 能用，Java 也能用，因为几乎所有语言都会"发 HTTP 请求"。而且调用方和 GSV 甚至可以不在同一台电脑上，只要把 `-a` 改成对外开放、对方能连到你的机器就行。
