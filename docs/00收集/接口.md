经过多年的发展，互联网行业已经有了许许多多的工具。在我们自己开发项目的时候，难免会想直接使用已有的工具来完善我们自己的项目。一般而言，工具方会提供一种叫作**接口**的服务，来给我们使用他们做的工具。

什么是接口？它是用来干嘛的？

接口就是提供服务方开的一个小窗户，你向他提供他需要的信息，他就会返回给你你想要的东西。比如买蜜雪冰城，前台肯定会问你一些问题（参数），“你要喝什么？”、“热的还是冰的？”、“几分糖？”、“要加小料吗？”......当你回答完这些问题，店员就会去做你要的奶茶。回到接口这边，你需要向提供服务方传入一些参数，这样提供服务方才能为你服务。

一个完整的接口由两部分组成，一个是请求方法，另一个是参数。前面已经讲过参数了，那什么是请求方法？简单来说就是**怎么把参数给到服务提供方**，常见的有 `GET` 和 `POST` 。还是用买奶茶举例，`GET` 给我的感觉就是口头交流，说完一句跟着一句；而 `POST` 就比较优雅，拿纸条工工整整地写。

我认为接口的作用有两个，一个是规范作用。如果没有接口，每个人向服务提供方传参数的时候传的都是不一样的，服务提供方还得一个个问，或者猜。有了接口，服务提供方一看就知道对方想要什么，效率就高了很多，这也是我认为的接口的第二个作用。

现在我们明白了接口是什么、怎么用，然后我们会面临一个问题：我怎么知道服务提供方有哪些服务？那些服务的接口是什么？

一般是是去 `README` 里面找，或者去源码里面找名字里面有 `api` 的文件。如果该项目的接口框架是 `FastAPI`，则接口的参数往往在 `/docs` 里面。

如我最近在玩的 `GPT-SoVITS` 项目，我先通过寻找 `.py` 文件，找到了接口服务的程序（下面的 `api.py`和 `api_v2.py`。
```bash
GPTSoVits) finderzly@finderzly-ROG-Strix-G16-G615LM-G615LM:~/Workspace/Tools/GPT-SoVITS$ ls *.py
api.py  api_v2.py  config.py  test_api_v2_streaming.py  test_official_streaming.py  webui.py
```

然后查看 `api_v2.py` 的前120行，看一下怎么用，因为一般而言，开发者会在开头写注释，讲解怎么用。
```bash
(GPTSoVits) finderzly@finderzly-ROG-Strix-G16-G615LM-G615LM:~/Workspace/Tools/GPT-SoVITS$ head -120 api_v2.py

"""
# WebAPI文档

` python api_v2.py -a 127.0.0.1 -p 9880 -c GPT_SoVITS/configs/tts_infer.yaml `

## 执行参数:
    `-a` - `绑定地址, 默认"127.0.0.1"`
    `-p` - `绑定端口, 默认9880`
    `-c` - `TTS配置文件路径, 默认"GPT_SoVITS/configs/tts_infer.yaml"`

```

执行 `api_v2.py` 开头出现的命令:
` python api_v2.py -a 127.0.0.1 -p 9880 -c GPT_SoVITS/configs/tts_infer.yaml `

就会打开一个web，里面啥也没有。
