## 二、远程连接 VPS
---

VPS 在云端，没法直接操作。我们用 SSH 连上去，连上之后你的命令行窗口就相当于 VPS 的终端。

打开命令行（Windows 用 cmd 或 PowerShell，Mac 用"终端"），输入：

```bash
ssh root@你的服务器IP
```

- 第一次连接会问是否信任这台主机，输入 `yes` 回车。
- 然后输入 root 密码。**输入密码时屏幕不显示任何字符，这是正常的**，输完直接回车。

看到命令行开头变成 `root@...` 就说明连上了。

## 三、安装 3x-ui
---

[[02学习/⭐概念/3x-ui|3x-ui]] 是一个网页管理面板，让你用点鼠标的方式配置节点，不用手写配置文件。

**1. 更新系统**

```bash
apt update && apt upgrade -y
apt install curl wget -y
```

**2. 运行安装脚本**

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

安装过程中脚本会问一些问题（比如要不要自定义面板端口），按提示选择即可。

**3. 保存面板信息**

安装结束后，终端会打印四样东西：**面板端口、访问路径、用户名、密码**。一定要截图保存。

忘了也没关系，随时可以用下面的命令查看：

```bash
x-ui settings
```

直接输入 `x-ui` 会打开管理菜单，可以在里面修改端口、用户名和密码。

## 四、放行端口
---

这一步决定了外面能不能连到你的服务器。需要放行的端口有两个：

|端口|用途|什么时候确定|
|---|---|---|
|面板端口|用浏览器打开 3x-ui|第三步安装时|
|节点端口|代理软件连接节点|第五步建节点时（推荐 443）|

> [!important] 很多人只放行了面板端口，结果面板能打开，节点却连不上。**两个都要放行。**

### 1. 系统防火墙

先看防火墙有没有开：

```bash
ufw status
```

- 显示 `inactive`：防火墙没开，跳过。
- 显示 `active`：执行下面的命令放行：

```bash
ufw allow 面板端口/tcp
ufw allow 节点端口/tcp
```

> [!warning] 自己开启 ufw 之前 一定要先执行 `ufw allow 22/tcp` 放行 SSH，否则开启后 SSH 会立刻断开，你就连不回服务器了。

### 2. 商家后台的防火墙

有些商家在网页后台还有一层防火墙（可能叫"防火墙""安全组"）。如果有，也要在里面放行这两个端口。

### 3. 打开面板

浏览器访问：

```
http://服务器IP:面板端口/访问路径/
```

如果安装时配置了证书，把 `http` 换成 `https`。用第三步保存的用户名和密码登录。

> [!tip] 更安全的做法（可选） 面板端口暴露在公网会被扫描。可以只放行节点端口，面板改用 SSH 隧道访问。在本地电脑运行：
> 
> ```bash
> ssh -L 8080:127.0.0.1:面板端口 root@服务器IP
> ```
> 
> 保持窗口不关，浏览器访问 `http://127.0.0.1:8080/访问路径/` 即可。
> 
> 不管用哪种方式，都建议把面板的默认用户名和密码改成自己的强密码。

## 五、创建节点
---

在面板里，**入站 = 节点，客户端 = 用户**。我们先建一个入站，再给它加一个客户端。

### 1. 添加入站

点击"入站列表" → "添加入站"，按下表填写：

|设置项|填写内容|
|---|---|
|备注|随便写，比如节点所在地"洛杉矶"|
|协议|[[02学习/⭐概念/VLESS\|VLESS]]|
|端口|**推荐 443**；被占用时改用 10000–65000 之间的端口|
|传输|TCP（默认）|
|安全|[[02学习/⭐概念/Reality\|Reality]]|

> [!note] 为什么推荐 443 Reality 会把你的流量伪装成访问某个正常网站的 HTTPS 流量，而 HTTPS 默认就走 443 端口，用 443 最不显眼。

### 2. 配置 Reality

选择 Reality 后，下面会出现几个新选项：

**目标（Target）和 SNI**：填同一个网站。这个网站要满足：

- 支持 TLS 1.3 和 HTTP/2（大公司官网一般都支持）；
- VPS 能正常访问，且在国内没有被墙。

格式上，"目标"填 `域名:443`（**冒号是英文冒号**），"SNI"只填域名。

![[09附件/Pasted image 20260925172640.png]]

**密钥**：点击"Get New Cert"，确认"公钥"和"私钥"两栏都出现了文本。

> [!note] 这一步生成的是一对密钥，不是网站证书。Reality 不需要申请证书。

其他选项（嗅探、高级配置等）保持默认，滑到最下面点保存。

### 3. 添加客户端

给自己用的话，建一个客户端就够了：

1. 添加客户端，在"关联入站"中选择刚刚建的节点；
2. **Flow 选择 `xtls-rprx-vision`**，这是 VLESS + Reality 推荐的搭配；
3. 保存。

## 常见问题
---

### 节点连不上

按顺序检查：

1. 节点端口有没有放行（系统防火墙和商家后台都要看）；
2. 客户端里的地址、端口、UUID、公钥、SNI 是否和面板一致（用导出链接一般不会错）；
3. 本地电脑的系统时间是否准确，时间差太多也会连不上。

### 链接导入 Clash Verge 失败

不同代理软件用的内核不同：

|软件|内核|
|---|---|
|v2rayN|[[02学习/⭐概念/Xray-core\|Xray-core]]|
|Clash Verge|Mihomo|
|Hiddify|sing-box|

这三个内核都支持 VLESS + Reality，问题出在**导入方式**：v2rayN 和 Hiddify 可以直接粘贴 `vless://` 链接；Clash Verge 主要使用 YAML 配置或订阅链接，直接粘贴不一定能导入。新手建议直接用 v2rayN。

### 全局链路图

![[09附件/ChatGPT_Image_2026年9月25日_17_44_54 1.png]]

### 一句话原理

**VPS 上运行代理服务端（Xray），你的设备作为客户端连过去，把流量加密后交给 VPS，由 VPS 替你访问目标网站。**

### 代理协议是什么

代理协议是**客户端（你的电脑）和代理服务器（VPS）之间约定好的一套通信规则**，它解决这些问题：

- 客户端怎么向服务器证明身份？
- 客户端想访问哪个网站，怎么告诉服务器？
- 数据怎么封装、加密、伪装？
- 服务器怎么把数据转发出去，再把结果传回来？

本教程用的 VLESS 就是一种代理协议，Reality 则负责伪装。

### 3x-ui 和 Xray 的关系

3x-ui 只是一个可视化面板，真正干活的是底层的 Xray。部署后：

1. Xray 在服务器的某个端口（如 443）上监听。服务器有公网 IP，只要有客户端连这个 IP + 端口，Xray 就会接收并处理。没有监听端口，外面根本找不到服务入口。
2. 面板生成连接信息（地址、端口、UUID、公钥等），也就是你导出的那段链接。
3. 你的代理软件用这些信息，主动连到服务器。

### 浏览器为什么会把请求发给 Xray

正常情况下，浏览器访问网站会直接连目标网站。但开了代理软件后，流量会先被它截下来：

1. 代理软件在本地监听一个端口（比如 10808），或者用 TUN 模式接管整个系统的网络；
2. 系统被设置成"所有流量先交给本地代理"；
3. 代理软件按节点配置把数据重新封装、加密，再发到 VPS 上 Xray 监听的端口；
4. VPS 解密后，替你访问真正的网站，再把结果传回来。

所以不是浏览器自己去连节点，而是代理软件在替你转发。不开代理软件，浏览器根本不会去连节点端口。

## 底层原理
---

### 核心原理

**远端服务器（VPS）运行代理服务端（Xray），你的设备作为客户端连过去，把流量加密后交给服务器（VPS）转发出去。**


### 3x-ui、Xray与代理

3x-ui 只是一个可视化面板，底层实际跑的是 Xray 。部署后它会：

1. 在服务器上监听指定端口（如 443），并配置好入站协议（如VLESS）。服务器有公网 IP，Xray 被配置成在某个端口（如 443）上“守着”。只要有客户端向这个 IP + 端口发起连接，Xray 就会接收并处理。没有监听端口，外面根本找不到服务入口。
2. 生成连接信息（地址、端口、UUID/密码、传输层配置等）。
3. 你的客户端用这些信息主动连到服务器的公网 IP 或域名。


### 为什么本地访问网站时会向Xray监听的端口发请求

因为装了代理客户端（如v2rayN、Clash Verge），并且把它设成了系统代理或开启了全局/规则模式。

正常情况下，浏览器访问网站会直接连目标网站的 80 或 443 端口。但代理客户端会先把这些流量截下来：

1. 它在本地监听一个端口（比如 1080 或 7890），或者用 TUN 模式接管系统网络。
2. 浏览器/系统被配置成“所有流量先走本地代理”。
3. 客户端拿到你要访问的网站请求后，按照节点配置（协议、UUID、加密方式等）把数据重新封装，然后主动连到远端服务器的监听端口。
4. 远端服务器解密后再帮你去访问真正的网站。

所以“向Xray监听的端口发信息”，其实是代理客户端在替你转发，而不是浏览器自己直接连过去。没有代理客户端接管流量，浏览器根本不会去连节点端口。
