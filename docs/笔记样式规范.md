这份规范用于统一整个笔记库的 Markdown 符号含义。不同类型的笔记可以使用不同结构，但同一种样式应尽量表达同一种意思。

核心原则是：**符号的含义统一，文章的骨架不必统一。**

## 快速判断

写完一段内容后，可以按照下面的顺序判断样式：

1. 它是关键词或逻辑重心吗？使用**粗体**。
2. 它是最终结论、决定或行动吗？使用==高亮==。
3. 它是代码元素吗？使用`行内代码`或代码块。
4. 它是别人的原话吗？使用引用。
5. 它是正文之外的补充、疑问、警告或例子吗？使用相应旁注。
6. 它们是并列项目、步骤还是待办事项？分别使用无序列表、有序列表或任务列表。
7. 它是否需要比较多个对象的相同字段？使用表格。
8. 前后内容是否跨越了不同时间、版本或文本性质？必要时使用分隔线。

如果一种样式只是为了“看起来更醒目”，却无法说明它具体表达什么，就先不要使用。

## 引用与旁注

### 引用

短引用或人物对话放在正文中，使用中文引号：

```md
老师说：“创建对象时，构造方法由虚拟机自动调用。”
```

需要单独呈现的原文摘录使用普通引用块，并尽量标明来源：

```md
> 构造方法在创建对象时被调用。
>
> ——《Java 基础教程》第三章
```

引用表示他人的原话或资料原文，不用来强调自己的结论。

### 旁注

旁注表示站在正文之外添加的信息。按照作用，使用以下四种常用类型。

已经确认的补充解释或个人理解：

```md
> [!note] 补充
> 无参构造方法没有显式参数，但方法名后仍然需要写 `()`。
```

尚未解决的问题或没有证实的猜测：

```md
> [!question] 待确认
> 老师为什么特别强调这一点？
```

容易出错、容易混淆或具有前提条件的内容：

```md
> [!warning] 注意
> 一旦手动定义了构造方法，虚拟机将不再提供默认的无参构造方法。
```

帮助理解抽象概念的具体情况：

```md
> [!example] 例子
> 汽车设计图可以看作类，依据设计图制造出的具体汽车可以看作对象。
```

如果自己的理解尚未确认，归入 `[!question]`；经过验证后，再改成 `[!note]`。

脚注暂不纳入常用格式。自己的补充、疑问和提醒使用旁注；引用资料时使用引用块并标明来源。

## 强调样式

### 粗体

粗体用于标记**关键词、核心概念和句子中的逻辑重心**，帮助阅读和理解。

```md
Layout 的本质是**复用页面外壳**。
```

不要给整段文字加粗，也不要把粗体当作普通装饰。

### 高亮

高亮用于标记==最终结论、已经作出的决定或需要执行的行动==，帮助以后快速回看。

```md
==以后多个页面出现相同结构时，优先考虑使用 Layout。==
```

粗体表示“理解这里时应当注意”，高亮表示“读完后需要带走”。

### 斜体

斜体只在个人写作中偶尔表达*轻微的语气强调或内心声音*，不作为知识笔记的固定结构。

```md
我看着空荡荡的球场，忽然想到：*原来我真的已经很久没打篮球了。*
```

引用和旁注内部默认使用正常字体，不额外使用斜体。

### 删除线

删除线只在保留旧内容本身有价值时使用，用来展示想法或理解的变化。

```md
我原本认为 ~~构造方法由程序员主动调用~~，后来才知道它由虚拟机自动调用。
```

如果旧内容只是写错了，没有保留价值，直接修改即可。整段观点已经过时时，使用带日期的回看旁注，不给整段文字加删除线。

## 分隔线

正文中的 `---` 表示时间、版本或文本性质发生明显切换，不作为标题装饰。

适合使用的情况：

- 原文与后续回看之间；
- 正文与参考资料之间；
- 自己的原稿与他人的修改稿之间；
- 两个不同时间或不同性质的写作阶段之间。

```md
这里是最初写下的想法。

---

## 2026-08-20 回看

这里是后来重新审视这件事时产生的新想法。
```

标题本身已经能够划分普通章节，因此不在每个标题下面重复添加分隔线。

文件开头用于包围属性区的 `---` 是 YAML 固定语法，不属于正文分隔线。

## 代码

### 行内代码

行内代码用于正文中出现的类名、方法名、变量名、命令、文件名和配置字段。

```md
使用 `Scanner.nextInt()` 读取整数，并将结果保存到变量 `score` 中。
运行 `pnpm build` 之前，检查 `package.json` 中的脚本配置。
```

`Java`、`C++`、`Astro` 等技术名称只是普通专有名词，不加反引号；`String`、`std::vector` 等具体代码元素需要加反引号。

不要用反引号表示强调、吐槽、疑问或普通英文单词。

### 代码块

完整代码或需要单独阅读、复制和运行的片段使用围栏代码块，并标明语言。

````md
```java
Scanner sc = new Scanner(System.in);
int score = sc.nextInt(); // 从标准输入读取成绩
```
````

程序输出、目录结构和执行流程等需要保留排版、但不属于代码的内容，使用 `text`：

````md
```text
读取人数
  ↓
创建数组
  ↓
逐个读取成绩
```
````

代码注释主要解释“为什么这样写”以及不容易直接看懂的逻辑，不重复代码已经清楚表达的内容。

## 数学公式

句子中的短公式使用行内公式：

```md
平均数可以表示为 $\bar{x}=\frac{1}{n}\sum_{i=1}^{n}x_i$。
```

需要单独观察的公式使用独立公式块：

```md
$$
\bar{x}=\frac{1}{n}\sum_{i=1}^{n}x_i
$$
```

只有需要展示 LaTeX 源码本身时，才把公式放进代码块。

## 列表

- 无序列表用于没有先后顺序、地位平等的并列项目。
- 有序列表用于步骤、流程、优先级或排名。
- 任务列表只用于以后确实需要完成并勾选的行动。
- 需要展开推理、叙述或表达情绪的内容保留为段落，不要为了整齐全部拆成列表。
- 列表最多嵌套两层；超过两层时，优先考虑拆分成小标题。
- 每一项是完整句子时，末尾加句号；只是词语或短语时，可以不加。

并列概念：

```md
- 无参构造方法
- 全参构造方法
```

操作步骤：

```md
1. 定义类。
2. 创建对象。
3. 通过对象调用成员方法。
```

实际任务：

```md
- [ ] 查清楚虚拟机为什么自动调用构造方法。
- [ ] 补充一个全参构造方法的例子。
```

## 表格

表格只用于横向比较具有相同字段的多个对象。

```md
| 类型 | 是否有参数 | 适用情况 |
|---|---|---|
| 无参构造 | 否 | 创建具有默认状态的对象 |
| 全参构造 | 是 | 创建时一次性设置全部属性 |
```

如果内容需要连续阅读、单元格里有大量文字，或者包含多层列表和大段代码，应当改用段落或标题。只有一列的普通事项使用列表即可。

## 链接与图片

### 内部链接

只有在读者可能需要跳转到另一篇笔记继续理解时才添加内部链接，不必给每次出现的概念都加链接。可以使用别名让句子读起来更自然：

```md
构造方法属于[[类和对象|面向对象]]的一部分。
```

### 外部链接

外部链接使用有意义的文字，不直接堆放网址：

```md
可以参考 [Java 官方教程](https://example.com)。
```

### 图片

图片单独占一行，前后留空行。图片说明直接写在下一行，不使用 Tab 缩进，以免被 Markdown 识别成代码块。

```md
![[../../附件/example.jpg]]

图：高二时拍下的一张照片。后面站着李昭汉。
```

如果图片下面是围绕图片展开的回忆或分析，直接另起正文段落，不必全部放进图片说明。

## 属性区

所有新笔记统一记录创建日期：

```yaml
---
createdDate: 2026-08-20
---
```

内容发生实质变化时，可以增加 `updatedDate`。只修改错别字、空格或排版时，不需要更新日期。

```yaml
---
createdDate: 2026-08-20
updatedDate: 2026-08-21
aliases:
  - 流
  - stream
tags:
  - C++
评分: 5
source: 《Java 基础教程》
---
```

- `aliases`：同一概念存在其他常见名称时使用，主要适合知识笔记。
- `tags`：用于跨目录归类；文件夹已经表达清楚的类别不重复标记。
- `评分`：用于追番、书影音等评价笔记。
- `source`：整篇笔记主要依据某一本书、一门课程或一份资料时使用。

属性区只保存以后确实会检索或使用的信息，不重复添加与文件名相同的 `title`，也不预先堆积大量“可能有用”的字段。

## 标题与结构

文件名就是整篇笔记的标题，正文通常不再重复书写一级标题。

- `## 二级标题`：笔记中的主要部分。
- `### 三级标题`：二级标题下的细分问题。
- `#### 四级标题`：仅在较长的知识笔记中使用，平时尽量不用更深层级。
- 标题负责划分内容结构，不用于强调一句话。
- 标题下面如果只有一两句话，通常改用粗体引导句，不必单独设立标题。
- 随笔和短篇思考可以完全不用标题，让文字自然展开。

知识笔记可以使用以下结构：

```md
## 是什么

……

## 怎么使用

### 创建对象

……

### 调用方法

……
```

按时间持续更新的笔记可以使用以下结构：

```md
## 2026-06-16

### 错因总结

### 电脑记笔记的逻辑

## 2026-06-11

### 反馈机制
```
