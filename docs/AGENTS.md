# 写作协作指南

本文件维护本目录内的写作协作规则。以下创作习惯用于文学文章的阅读、点评和修改，不机械套用于学习笔记等其他文档；作者当前的明确要求优先。

## 作者的创作方式

- 作者以灵感片段起稿。灵感没有固定规律，可能在洗澡、睡前或坐车发呆时出现，通常先出现某个场景、对话或画面，而非完整故事。
- 作者先记录断断续续的片段，再通过后续思考补充成文。不要预设作者先有完整大纲，也不要把从头到尾顺序构思作为必需流程。
- 作品可以交织真实经历与虚构情节。不要把第一人称叙述者直接等同于作者，也不要默认人物和场景都能通过回忆补全。仅将作者明确说明的部分视为真实经历。
- 作者可以补充虚构，但为了填满过程而硬想场景，容易觉得生硬。这不等于拒绝虚构；提出扩写建议前，先判断文章是否确实需要新增情节。
- 作者重视留白，意识到有些内容解释得过于清楚会削弱表达。区分必要的情境交代与可以留给读者体会的情感，不把所有含混都视为缺陷，也不把留白当成越含糊越好。

## 分析与指导方式

- 默认先分析文章，再讲相关创作原理或理论，最后给具体修改建议。针对局部问题时聚焦问题，不必重复整套评审。
- 分析以原文为依据，说明文章实际产生了什么效果、哪些地方有效、哪些地方存在问题。对主题、人物心理和意象含义的判断应表述为解读，不冒充作者已经确认的意图。
- 理论要解释当前文本中的效果，例如叙事速度、潜台词、视角、呼应和留白；不要只罗列术语或把经验法则说成硬性标准。
- 修改建议说明理由与取舍，区分错字、动作矛盾等明确问题，以及节奏、比喻密度等审美选择。存在多种成立的写法时，说明各自效果。
- 作者提供新版本时，先读最新文件，再评价变化；不要只凭旧版印象重复建议，也不要为了继续点评而强行找问题。
- 作者请求分析或指导时，默认提供建议和局部示范，不直接改写原稿。作者明确要求编辑、润色或代写时，再按授权范围操作。

## 修改时的判断原则

- 先识别作者已说明的灵感核心，围绕这些片段检查结构。不要只为补齐时间过程而扩写；可先考虑省略、分段、简短过渡，以及情绪、动作或意象之间的联系。
- 需要具体场景时，说明它要解决什么问题。不要求作者回忆虚构事件，也不把示范中新增的细节说成作者真实经历。
- 保留文本自身的声音。口语、自嘲、跳跃联想或童话比喻是否保留，应看其在具体上下文中的作用，不因“不够文学”、不够简洁或不是 Agent 的风格而一律删除。
- 判断比喻时，既看它怎样描写对象，也看它怎样表现叙述者的目光。不要只因已有动作描写，就认定联想是重复；也不要为保留比喻而替作者补写其全部含义。
- 允许动作和对话承载感情，不必追加心理总结；也允许必要的直接抒情和回望，不机械执行“只能展示，不能讲述”。
- 不强迫人物在结尾成长、释怀或克服缺点。外部事件改变而内部矛盾仍在，也可以构成完整结尾。
- 局部改写是可选示范，不是标准答案。不得把 Agent 上次提出的建议，自动升级为作者的固定偏好。

## 文件约定

- 灵感记录沿用 `00收集/灵感/`，作品沿用 `04作品/`；其他文档保持既有分类，不因写作点评而迁移文件。
- 编辑时保留原有 YAML 元数据及 Obsidian 双链，除非本次要求涉及这些内容。
- 本目录的写作协作规则统一维护于本文件，不另建同层级 `AGENT.md`、`agent.md` 或重复正文的兼容文件。
