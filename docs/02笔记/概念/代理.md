# 一、先建立一张“层”的地图

网络通信分层，每层只管一件事，下层给上层干活。

|层|管什么|例子|比喻|
|---|---|---|---|
|**应用层**|传什么内容|HTTP、DNS，**VLESS、Trojan、Shadowsocks 也在这层**|信的内容|
|**（安全层）**|加密|**TLS、Reality**|把信锁进保险箱|
|**传输层**|怎么送（可靠还是不管）|**TCP、UDP**|挂号信还是平信|
|**网络层**|送到哪台机器|IP|收件地址|
|**链路层**|这一小段线路怎么传|以太网、Wi-Fi|快递车|

TLS 夹在传输层和应用层之间，所以常被叫作“第 4.5 层”。

## 代理协议让人懵的原因：它是“套娃”

正常上网只有**一套**分层。用代理时，会出现**两套**：

```
外面这套：你的电脑 ↔ 你的 VPS（GFW 看得到的就是这套）
  IP 层       目标：VPS 的 IP
  TCP 层      目标端口：443
  Reality 层  加密，伪装成访问 microsoft.com
  VLESS 层    “我是 UUID xxx，帮我去连 youtube.com:443”
    ↓ 以下全部被装在 VLESS 里面，GFW 看不到
里面这套：你的浏览器 ↔ YouTube
  TLS 层      浏览器和 YouTube 自己的 HTTPS 加密
  HTTP 层     “给我这个视频”
```

**所以 VLESS 这类代理协议是应用层协议，但它的“内容”是另一整套网络通信。** 这就是套娃。

Hysteria2 的外面那套稍有不同：

```
IP 层 → UDP 层 → QUIC（自带 TLS 1.3 加密） → Hysteria2 认证与代理 → 里面那套
```

# 二、握手：打开 YouTube 时一共握了几次手

**握手**的意思就是：**正式传数据之前，双方先来回几次，把一些事情商量好。** 不同层的握手商量的事情不同。

按时间顺序走一遍：

```
你的电脑                         你的 VPS                       YouTube
   │                               │                               │
 ① │ ── TCP 握手（3 次）─────────→ │                               │
   │    商量：连接建立了吗？          │                               │
   │                               │                               │
 ② │ ── Reality 握手 ────────────→ │                               │
   │    商量：用什么密钥加密？        │                               │
   │    顺便：你是不是自己人？        │                               │
   │                               │                               │
 ③ │ ── VLESS 请求 ──────────────→ │                               │
   │    “我是 UUID xxx，             │                               │
   │     帮我连 youtube.com:443”    │                               │
   │                               │                               │
   │                             ④ │ ── TCP 握手 ────────────────→ │
   │                               │    VPS 替你连 YouTube           │
   │                               │                               │
 ⑤ │ ═══ 浏览器和 YouTube 的 TLS 握手，经过隧道 ════════════════════→ │
   │    商量：浏览器和 YouTube 之间用什么密钥                          │
   │                               │                               │
 ⑥ │ ═══ 看视频的数据 ═══════════════════════════════════════════════│
```

|次序|谁和谁|商量什么|属于哪层|
|---|---|---|---|
|①|你 ↔ VPS|建立连接|TCP（传输层）|
|②|你 ↔ VPS|加密密钥，以及认证身份|Reality（安全层）|
|③|你 → VPS|认证 UUID，告诉 VPS 目标地址。**严格说这不算握手，只发一次**|VLESS（应用层）|
|④|VPS ↔ YouTube|建立连接|TCP|
|⑤|浏览器 ↔ YouTube|内层加密密钥|TLS|
|⑥||开始传数据||

**关键点：**

- ① ② ③ 是**外面那套**，GFW 能看到 ① 和 ② 的明文部分。
- ⑤ 是**里面那套**，被包在 ② 的加密里，GFW 看不到。
- ⑤ 这次握手被包在外层加密里面，就是上次说的“**TLS 套 TLS**”，Vision 要处理的就是它。

# 三、加密：每一层是谁加的，用什么钥匙

## 先抓住一条主线

几乎所有协议都是这样：

> **先用某种办法让双方得到同一把钥匙，再用这把钥匙对数据做对称加密（AES 或 ChaCha20）。**

**加密数据的方法大家都差不多，区别在于钥匙是怎么来的。**

## 各协议的钥匙从哪来

|协议|钥匙怎么来|怎么确认对方身份|
|---|---|---|
|**Shadowsocks**|**事先约定的密码**，每次连接加一个随机盐值派生出新钥匙|能用密码解开，就是自己人|
|**VMess**|由 **UUID** 派生|UUID 加时间戳|
|**Trojan**|**标准 TLS 握手**现场协商|服务器靠 **CA 证书**证明身份；客户端靠密码证明身份|
|**VLESS**|**自己不加密**，全靠外面套的 TLS 或 Reality|UUID|
|**Reality**|**标准 TLS 1.3 握手**现场协商（X25519 密钥交换）|服务器靠**你配置里的公钥 `pbk`** 证明身份，不靠 CA；客户端把认证信息藏在 `session_id` 里|
|**Hysteria2**|**QUIC 自带的 TLS 1.3** 现场协商|服务器靠证书（可以是自签的）；客户端靠密码|

两种钥匙来源的区别：

- **事先约定**（Shadowsocks、VMess）：简单，但没有标准的握手过程，所以流量“什么都不像”。
- **现场协商**（Trojan、Reality、Hysteria2）：用的是 TLS，和正常网站一模一样，**更好伪装**。

## 放回你的节点：一共几层加密

```
GFW 看到的：     [Reality 加密  ████████████████████████]
你的 VPS 解开后： [VLESS 头：UUID + youtube.com][████ 内层 TLS 加密 ████]
YouTube 解开后：                                [看视频的 HTTP 请求]
```

- **Reality 这层**：防 GFW。
- **内层 TLS**：浏览器和 YouTube 自己加的，**连你的 VPS 也看不到具体内容**。
- **VLESS 不加密**，因为外面已经有 Reality，再加一层就是浪费。

# 四、代理攻防：GFW 在问三个问题

前面列了 8 种检测手段，可以归成 **GFW 想搞清楚的三个问题**：

### 问题 1：“你在连谁？”

- 看 **IP**：是不是已知的代理服务器？
- 看 **SNI**（TLS 握手里明文写的域名）：是不是被禁的网站？

### 问题 2：“你用的是什么协议？”

- 看**格式**：有没有某个协议固定的字节？
- 看**指纹**：TLS 握手像不像真浏览器发的？
- 看**统计规律**：随机程度、包大小、流量大小正常吗？

### 问题 3：“我亲自去敲门，会怎么样？”

- **主动探测**：GFW 假装成客户端连你的服务器，看它怎么回应。

## 各协议怎么回答这三个问题

||问题 1：连谁|问题 2：什么协议|问题 3：敲门|
|---|---|---|---|
|**Shadowsocks**|一个普通 IP|全是乱码，**但“什么都不像”本身可疑** ❌|老版本反应异常 ❌|
|**Trojan**|**你自己的域名**，可能被盯上 ❌|像 HTTPS，但指纹和 TLS 套 TLS 会露馅 ⚠️|看到一个正常博客 ✅|
|**VLESS + Reality**|SNI 写的是大网站 ✅，但 IP 不是那个网站的 ⚠️|模仿 Chrome 指纹，Vision 处理 TLS 套 TLS ✅|**看到的是真的大网站** ✅|
|**Hysteria2**|普通 IP|像 HTTP/3 ✅，但长时间大流量 UDP 可疑 ⚠️|看到一个正常网站 ✅|

**规律：每一代协议都在补上一代被抓住的漏洞。** Reality 已经把三个问题都回答得比较好了，剩下的弱点只有“IP 本身被封”，以及 TCP 在烂线路上慢。Hysteria2 换到 UDP 解决速度问题，但又带来了“UDP 容易被限”的新问题。所以你的项目两个都装。

# 五、一句话版本

1. **分层**：IP 管送到哪台机器，TCP/UDP 管怎么送，TLS 和 Reality 管加密，VLESS 管“我是谁、要去哪”。
2. **套娃**：代理协议里面装着另一整套通信（浏览器 ↔ YouTube）。
3. **握手**：每层在传数据前各自商量一次。你的节点外层有 TCP 和 Reality 两次握手，里层还有浏览器和 YouTube 自己的 TLS 握手。
4. **加密**：各协议加密数据的方法都差不多，区别在钥匙怎么来：事先约定，还是用 TLS 现场协商。
5. **攻防**：GFW 问三个问题：你连谁、你用什么协议、我去敲门会怎样。协议设计就是让这三个问题都得到“看起来很正常”的回答。
