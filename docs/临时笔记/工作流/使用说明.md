# 文件结构与使用说明

这份工作流共 4 份文件。真正的"给 AI 的文本"只有三份：两份 prompt + 一个模板。
本文件是给你自己看的说明，不发给 AI。

## 文件清单

| 文件 | 作用 | 谁用 |
|---|---|---|
| `提示词：讨论阶段.md` | 项目启动时的架构讨论；产出 AGENT_CONTEXT.md | 你 + 网页端 GPT |
| `提示词：生成Plan以及Phase.md` | 讨论完生成工程执行 Plan | 你 + 网页端 GPT |
| `AGENT_CONTEXT.md模板.md` | 仓库内唯一状态源 + 共享规则源，随项目提交 | GPT 更新 / Agent 读取 |
| `使用说明.md`（本文件） | 文件职责、使用流程、旧版对照 | 你自己 |

## 使用流程

1. **讨论**：把《讨论阶段》整段贴给网页端 GPT，开始聊项目。每轮结束 GPT 会
   检查新决策并更新 AGENT_CONTEXT.md 对应章节。
2. **生成 Plan**：说"开始生成 Agent Plan"。GPT 按《生成Plan以及Phase》生成，
   把生成的 Plan 存进 AGENT_CONTEXT.md（或作为独立 PLAN.md）。
3. **Agent 执行**：把某个 Phase 的指令（含"先读 AGENT_CONTEXT.md"）贴给 Trae。
4. **Review**：把 Agent 的 Report 贴回 GPT，GPT 审证据后给 Accept/Refuse 和
   下一轮指令。
5. **开新对话**：对 GPT 说"读一下仓库里的 AGENT_CONTEXT.md 继续"，无缝续接。

## 为什么这么分（核心设计）

- **AGENT_CONTEXT.md 是唯一状态源**：GPT 和 Trae 没有共同记忆，唯一共同场所是
  仓库。所有"当前状态"进文件，对话不承载状态。长上下文丢失、跨文件漂移、
  每次重写全局规则，都由这一份文件解决。
- **共享规则集中在模板里**：Agent 全局规则、Git 工作流、回滚协议、Review 验收
  规则只写一份，两份 prompt 都引用。改一处生效全局，不会出现"两个文档漂移"。
- **prompt 只留指令**：去掉了所有解释性文字，复制即用，长度减半。

## 与旧版对照

| 项目 | 旧版 | 新版 |
|---|---|---|
| 状态载体 | 对话文本 | AGENT_CONTEXT.md |
| 决策触发 | "重要就记"（模糊） | 每轮强制检查，无则明说"本轮无新决策" |
| 阶段总结 | 给人看的摘要 | 高密度快照，可整段贴新对话续接 |
| Phase 粒度 | "适合一次执行"（模糊） | 硬上限：≤5 文件 / ≤300 行 / 必须有可自动验收项 |
| 依赖 | 只写"依赖：Phase X" | 引用契约表编号 + 显式接口签名 |
| Report | 空字段"测试结果" | 证据化：测试命令 + 原始输出 + diff 统计 + 文件清单 |
| 验收 | 看报告空字段 | 审证据；缺证据 / 契约不符 / 测试盲区 → Refuse |
| 失败处理 | 无 | 回滚协议 + 连续两轮不过回炉重评 |
| 全局规则 | 每份 prompt 各写一遍 | 集中在 AGENT_CONTEXT.md，唯一副本 |
| 下一轮指令 | 对话里生成 | 自含上下文 + 写入文件 |

## 可调参数（只调模板和 prompt 中的数值，不要破坏结构）

- Phase 上限：5 文件 / 300 行 / 1 个可自动验收项
- 连续失败重评阈值：同一 Phase 修两轮不过 → 回炉
- 契约表：任何新增跨模块接口必须登记，这是硬规则
