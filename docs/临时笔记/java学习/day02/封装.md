## 解决什么问题

学完了[[类和对象]]，那么很自然地就会问：**如何正确地，啊不，科学地设计一个类**？

## 封装的含义

一个类里面，不但要有这个类的相关数据——属性，还得提供**处理这些数据的方法**。

举个例子：“人画圆”。画圆这个方法是定义在人的类里面，还是定义在圆的类里面？关键在于画圆需要**半径**这个数据，而半径是圆的属性，因此，画圆这个方法在圆里面。人只是调用了圆对象的画圆方法，圆自己把自己画出来了。

第二个例子：“人关门”。门有一个属性：开关。那么就要提供处理这个属性的方法，也就是开门与关门。因此开关门得定义在门里面，人只是调用了门的关门方法。

==判断的核心在于：这个方法要处理的数据是属于哪个对象的？==

## 封装的好处

对我而言最大的好处就是学习成本降低。Java开发者已经封装的很多常用的类，在我需要的时候我去查手册，然后创建对象、调用方法就可以直接使用了

## private[[../day01/关键字|关键字]]

权限修饰符，用于定义类的成员，被private修饰的成员只能在当前类中被访问。

## 关于封装的新理解

我以为是：只要一个方法涉及到类的属性，那么就要把它定义在类里面。但是其实不是，就拿学生管理系统来说明，我如果想在类里面去实现”查询学生“的功能，就会面临一个问题：去哪里查？

因此，封装在类里的方法应该是：**会==直接==访问或操作类的成员变量的方法**。比如：`set()`。

我感觉还是不太合理，于是问gpt：“但是好像不能说删除不是直接的吧？只是因为我调用了其他方法，所以才不直接。”
>对，你发现了问题：**“是否直接操作成员变量”这个标准不够准确**。调用了其他方法，并不代表这个功能就不属于这个类。真正要看的是：**这个操作最终改变的是谁的状态。**

因为学生管理系统中，增删查改操作改变的是**学生系统**，也就是arraylist的状态，因此不是定义在`Student`类里面。
